# 欢迎来到我的博客

这个站点最初只是一个用来放文章的页面。后来文章多了一些，功能也慢慢长出来：搜索、归档、点赞、评论、通知、阅读统计、后台管理，还有一些和 AI 相关的实验。它逐渐不再只是一个发布内容的地方，而成了我用来练习完整交付的一块长期实验场。

## 为什么还要自己维护一个博客

在社交平台上写东西更快，也更容易得到即时反馈，但内容的展示方式、排序方式和生命周期都不完全由自己决定。个人博客的速度慢一点，却可以让我决定文章怎么组织、项目如何展示，以及哪些失败过程值得保留下来。

我也把它当作一个真实的软件项目来维护。文章不是填充页面的占位符，搜索和归档不是演示按钮，部署也不能只在本地成功。每一个看起来很小的功能，都有接口、数据、缓存、权限和异常处理需要面对。

## 这里会记录什么

一部分内容来自后端、前端和部署实践，比如 Spring Boot 升级、Redis 状态设计、Docker Compose 的服务编排，以及低配服务器上如何做取舍。另一部分内容会记录研究生阶段的学习、项目和写作。技术文章不一定要像文档一样冷静，个人文章也不需要假装没有方法。

我更愿意写那些经过真实过程的问题：为什么一个看似合理的方案最后没有采用，某次故障是怎样定位的，一个 AI 功能怎样从概念入口变成有边界的工具。这样的文章也许没有标准答案，但至少能留下判断发生的过程。

## 这个博客目前的边界

它不是一个大规模内容平台，也没有必要假装拥有复杂的分布式能力。现在的系统仍然是一个可解释的单体应用：MySQL 保存文章事实，Redis 处理缓存和短状态，RabbitMQ 承担通知等异步任务，Nginx 负责公网入口，React 和 Spring Boot 共同完成阅读和管理体验。

我会优先把这些基础路径做稳，再考虑增加新的实验。一个功能如果只能在截图里看起来不错，却无法解释失败时怎么办，那它就还没有真正完成。

## 以后想继续做的事

我希望把文章和项目之间的关系做得更自然：读一篇技术文章时，可以看到对应的代码和部署说明；看一个项目时，也能找到它背后的取舍记录。还会继续补充更真实的测试、故障复盘和长期运行数据，而不是只在上线当天记录一个“部署成功”。

欢迎你从任何一篇文章开始阅读。这里不追求每次更新都很快，只希望每次写下来的东西，都比上一篇更具体一点，也更接近我真正做过、想过和验证过的事情。
