# My Blog Platform

## 一句话定位

一个真实运行在公网的全栈内容基础设施：从文章编辑、发布、阅读、评论，到缓存、异步通知、实时连接和容器化部署，形成完整闭环。

## 求职版项目描述

独立设计并上线一套生产可访问的个人内容系统，采用 React 19 + TypeScript 前台、Vue 3 管理台、Spring Boot 3 后端和 Docker Compose 部署；围绕高频读路径、异步副作用和线上可靠性，引入 Redis 缓存与限流、RabbitMQ 消息投递、STOMP WebSocket 实时通知、JWT/RBAC 认证和 Nginx 安全边界。

## 三个可以展开的面试问题

### 为什么不是简单的 CRUD 博客

文章列表、搜索和归档是高频读路径，详情页还会触发点赞、评论、实时在线人数等附加链路。因此系统把摘要 DTO、缓存、异步通知和前端按路由拆包分开处理，避免阅读主链路被非核心能力拖慢。

### 为什么要引入消息队列

评论后的邮件通知、操作日志和实时提醒都不是用户必须等待的结果。RabbitMQ 负责持久化投递、手动确认和失败兜底，WebSocket 负责把已经完成的事件推给在线用户。

### 如何证明它不是只停留在代码里

仓库提供 CI 质量门禁、服务器 smoke 检查、k6 读路径压测脚本、架构说明和运行手册；线上通过 Docker healthcheck、Nginx 代理边界和独立数据卷保持可恢复运行。
